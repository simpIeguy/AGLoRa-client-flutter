# CLAUDE.md (client-app)

Правила приложения «Поиск БЛА». Общие правила (безопасность, владелец, протокол BLE, экономия контекста) лежат в корневом `../CLAUDE.md` и действуют здесь тоже.

## Решения владельца (ТЗ-2)

- Своя версия: синхронизация с оригинальным проектом не нужна, упоминаний оригинала и автора нет. Совместимость **протокола** с прошивкой обязательна.
- Только Android, идентификатор `by.tsp.tracker`. Папка `android/` в git, папку `ios/` не создавать.
- Интерфейс только на русском. Все тексты в `lib/ui/strings.dart`, в экранах строк нет.
- Критерий для новой функции: помогает ли она быстрее найти трекер (в первую очередь упавший БЛА). Говорить «трекер», а не «дрон», где это возможно.
- Владелец собирает и ставит сам, на Windows 11. Объясняй каждый шаг простыми словами.
- Можно без спроса: `flutter pub get`, `flutter analyze`, `flutter test`, `flutter build apk --debug`.
  Установку на телефон (`flutter install`, `flutter run`, `adb install`) делай только после моего "да".
- Bluetooth в эмуляторе Android не работает: подключение проверять только на телефоне.
- В `AndroidManifest.xml` только нужные разрешения: интернет (плитки карты), Bluetooth (`BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT`;
  для старых Android `BLUETOOTH`, `BLUETOOTH_ADMIN`), геолокация (`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`). Ничего лишнего.
- Пакеты: версии в `pubspec.yaml` не обновлять без согласия, `flutter pub upgrade` не запускать. `flutter_map 5.0.0`,
  `wakelock_plus 1.3.3` (новее откатывает `flutter_blue_plus`) и `shared_preferences 2.5.6` закреплены жёстко.
  Новый пакет сначала проверить `flutter pub add <пакет> --dry-run`. Если сборка падает из-за версий, объясни причину и предложи варианты.
- Протокол BLE общий для прошивки, приложения и эмулятора (раздел «BLE protocol» в `../CLAUDE.md`).

Карта кода (`client-app/lib`):

| Папка | Что там | Правило |
|---|---|---|
| `protocol/` | склейка кусков BLE, разбор сообщений, имена UAV/GROUND | чистый Dart без Flutter, полностью покрыт тестами |
| `data/` | `TrackerStore` (единственный источник правды о трекерах), статусы, порядок списка, стрелка, лампочки | логика без виджетов |
| `services/` | Bluetooth и подключение, GPS телефона, компас, часы, настройки, память, ссылки на карты, `AppServices` | каждый сервис подменяется в тестах |
| `demo/` | демо-режим: сценарии `assets/demo/*.txt` и их проигрыватель | |
| `ui/` | экраны, виджеты, `theme.dart`, `strings.dart`, `format.dart` | только показывают и передают действия |

Правила:
- Новая функция = код + тесты + демо-сценарий (при необходимости) + проверка скриншотами + тексты в `strings.dart`.
- Глобальных изменяемых переменных нет: состояние живёт в `AppServices`, экраны получают его через `AppScope.of(context)`.
- Цвета и размеры только из `lib/ui/theme.dart` (`AppPalette` по темам, `AppSizes`; `AppColors` только для карты). Нажимаемые элементы не меньше 48 dp.
- Логирование только через `appLog` (`lib/util/log.dart`), `print` запрещён анализатором.
- Маленькие шаги, отдельные коммиты, перед коммитом `tool/check.ps1`.

## Dart MCP и навыки Flutter (плагин `dart-flutter`, включён для проекта)

- Плагин даёт сервер Dart MCP (дерево виджетов, ошибки времени работы, горячая перезагрузка) и навыки `flutter-*` / `dart-*`. Они общие, правила проекта выше важнее.
- Если приложение уже запущено (эмулятор или телефон) и ты правил `.dart` в `lib/` (не комментарии и не `test/`): подключись через инструмент `dtd` и сделай `hot_reload`. После правки `main()`, `initState` или глобального состояния делай `hot_restart`.
- Запускать приложение на телефоне, а также `pub add` / `pub upgrade` через MCP можно только после моего «да» (правила про установку и версии пакетов выше действуют и для MCP).
- Для вёрстки и переполнений используй навык `flutter-fix-layout-issues`, для шлифовки интерфейса сначала проверь `widget_inspector` и скриншоты.
