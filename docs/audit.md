# Аудит приложения (ТЗ-2, этап 2)

Состояние кода до перестройки (ветка `dev`, коммит `f5343fb`) и что с ним сделано в ветке `foundation`.

## Как был устроен код

- `lib/aglora/`: склейка кусков Bluetooth в сообщения (`aglora.dart`, `package_finder.dart`), разбор сообщений (`parser_*.dart`, `package_manager.dart`), хранилище точек (`memory.dart`).
- `lib/utils/`: Bluetooth, компас, статусы трекеров, ссылки на карты.
- `lib/screens/`: экраны и карточки. В карточке трекера (348 строк) вперемешку лежали расчёт расстояния, подписка на GPS, таймеры и вёрстка.

Путь данных: Bluetooth-уведомление → `newDataReceiver` → общая строка `_bleDataStack` → поиск сообщений → разбор → `agloraAppMemory.addPoint` → поток `dataStreamController` → экран.

## Глобальное состояние и чем оно опасно

| Что | Где | Опасность |
|---|---|---|
| `_bleDataStack`, `_blePreviousData` | aglora.dart | общий буфер на всё приложение: при смене трекера или демо в нём оставались куски старых данных |
| `agloraAppMemory` | memory.dart | любой экран мог менять точки, тесты мешали друг другу |
| `dataStreamController`, `compassStreamController` | data.dart, compass.dart | никогда не закрывались; экран, открытый позже точки, не получал её без обходных путей |
| `useCompass` | saved_parameters.dart | переключатель жил в переменной, экраны узнавали об изменении случайно |
| `activeDataSource` | data_source.dart | один источник на всё приложение без явного владельца |

Сейчас всё это живёт в объекте `AppServices`. Он создаётся один раз в `main()` и передаётся экранам через `AppScope`. В тестах для каждого теста создаётся свой объект.

## Фильтр одинаковых кусков (`_blePreviousData`)

Фильтр отбрасывает кусок, если он в точности равен предыдущему. Настоящие данные он может потерять, только когда два соседних куска по 20 байт совпадают целиком. Внутри одного сообщения так почти не бывает: в каждом куске свои координаты и время. Два одинаковых сообщения подряд по 20 байт или короче прошивка не шлёт. Риск низкий, поэтому фильтр оставлен как был, а потерянная точка придёт со следующей отправкой. Если на телефоне будут пропадать точки, первым делом стоит проверить его.

## Найденные ошибки (исправлены при перестройке)

1. Сообщение `memory` без `dev_name` (так прошивка отвечает на `id<N>` при пустой памяти) сбрасывало «подключённый трекер», и синяя карточка становилась обычной. Теперь имя без `dev_name` не сбрасывается.
2. Если префикс `AGLoRa-` разрывался между двумя кусками («…AGLo» + «Ra-point…»), сообщение терялось. Теперь начало префикса сохраняется.
3. Проверка `CRC_ERROR` в `package_manager.dart` ничего не делала: `return` внутри `forEach`. Убрана как мёртвый код.
4. Каждая карточка сама подписывалась на GPS телефона. Подписка теперь одна на всё приложение.
5. Разбор полей точки удалял элементы списка прямо во время обхода и работал только при «удачном» порядке полей. Переписан без этого.
6. В интерфейсе оставались английские надписи: Back, Map, distance, minutes ago, Connect, Use your compass и другие. Все тексты теперь в `lib/ui/strings.dart`, на русском.

## Android

- Разрешения в манифесте: интернет, `BLUETOOTH_SCAN` и `BLUETOOTH_CONNECT` (Android 12+), `BLUETOOTH` и `BLUETOOTH_ADMIN` до Android 11, геолокация. Для Android 12+ этого достаточно, пока приложение работает на экране.
- `targetSdk` берётся из Flutter (сейчас 36). При выключенном экране Android усыпляет приложение, и связь с трекером может оборваться. Для работы в фоне нужна служба переднего плана с уведомлением (ТЗ-3, блок 5).
- Если Bluetooth-связь пропала, приложение само не переподключается: кнопка «Подключить» в шапке. Автоматическое переподключение тоже относится к блоку 5.
- Число спутников телефона: библиотека геолокации отдаёт его только на Android и только через пакет `geolocator_android`. Его нужно явно записать в `pubspec.yaml`, это нужно согласовать.
